## Summary

Introduce a tiered EDI parsing API to `ballerina/edi` that allows consumers to read EDI documents at varying levels of depth, from schema-free envelope peeking to full deep parsing, without requiring multiple passes over the document. The API also adds first-class support for header and trailer segments in the schema, enabling correct envelope-aware parsing for X12 and EDIFACT.

## Motivation

The current `ballerina/edi` library exposes a single entry point, `fromEdiString`, which performs a full deep parse of the entire EDI document. This creates several practical problems:

- Schema selection requires content inspection. In real-world integrations, the incoming EDI message must first be inspected (for example, read the ISA/UNB segment) to determine which schema to apply. Today this forces a raw string scan before the library can be used.
- No schema-less routing. Message brokers and routing layers need to extract sender, receiver, and message-type information without loading a schema at all. The library provides no facility for this.
- Envelope validation is expensive. Confirming that ISA/IEA segment counts are correct today requires a full deep parse even though the envelope segments are structurally trivial.
- Body forwarding/splitting. When an application needs to forward or split an EDI interchange, parsing the entire body into typed records and then re-serializing is wasteful. The body can stay as raw strings while the envelope is parsed.
- Schema omits envelope segments. X12 and EDIFACT schemas generated by `edi-tools` currently strip ISA, GS, UNB, and UNH from segments using `ignoreSegments`. There is no structured way to parse or validate them.

The EDI ecosystem (X12, EDIFACT) explicitly separates the interchange envelope from the transaction body. The library should reflect this structure.

## Goals

- Provide a schema-free API for extracting X12 and EDIFACT envelope headers without loading a schema.
- Provide a schema-driven API that stops parsing immediately after the header segments.
- Provide a schema-driven one-pass API that parses the envelope (header + trailer) and returns the body as raw segments.
- Add `headerSegments` and `trailerSegments` fields to `EdiSchema` so envelope segments are handled explicitly rather than silently ignored.
- Define standard Ballerina types for X12 (`ISA`, `GS`) and EDIFACT (`UNB`, `UNH`) envelope elements, reusable across generated libraries.
- Maintain full backward compatibility: `fromEdiString` is unchanged; old schemas (without `headerSegments`/`trailerSegments`) continue to work with `fromEdiString`.
- Provide actionable errors when new API functions are called with old schemas that lack the required fields.

## Non-Goals

- Parsing X12 functional groups (`GS`/`GE`) as envelopes (out of scope for this proposal; handled by `headerSegments`).
- Implementing `peekSegments()` for raw segment-level access (deferred to future work).
- Auto-generating `headerSegments`/`trailerSegments` in `edi-tools` as part of this BEP (tracked separately).
- Supporting EDIFACT `UNG`/`UNE` (group-level) envelopes beyond what `headerSegments` already enables.
- Changing the serialization path (`toEdiString`).

## Design

### 1. Schema changes
Two new optional fields are added to `EdiSchema`. Both default to `[]` so existing schemas are unaffected:

```bal
public type EdiSchema record {|
    string name;
    string tag = "Root_mapping";
    record {| string segment; string 'field; ... |} delimiters;
    string[] ignoreSegments = [];
    boolean preserveEmptyFields = true;
    boolean includeSegmentCode = true;

    EdiUnitSchema[] headerSegments = [];   // NEW: parsed before body segments
    EdiUnitSchema[] segments = [];         // existing
    EdiUnitSchema[] trailerSegments = [];  // NEW: parsed after body segments
|};
```

`edi-tools` will be updated (in a follow-up) to populate these fields automatically when converting X12 XSD or EDIFACT message definitions.

### 2. Standard envelope types (shipped in `ballerina/edi`)
These types represent the standard interchange envelopes for X12 and EDIFACT. They are defined once in the library and reused by generated packages.

```ballerina
public type X12ISA record {|
    string authInfoQualifier;
    string authInfo;
    string securityQualifier;
    string securityInfo;
    string senderQualifier;
    string senderId;
    string receiverQualifier;
    string receiverId;
    string date;
    string time;
    string version;
    string controlNumber;
    string usageIndicator;
|};

public type X12GS record {|
    string functionalIdentifier;
    string senderId;
    string receiverId;
    string date;
    string time;
    string controlNumber;
    string version;
|};

public type X12Headers record {|
    X12ISA isa;
    X12GS gs?;
|};

public type X12SE record {|
    int segmentCount;
    string controlNumber;
|};

public type X12Trailers record {|
    X12SE se;
|};

public type EdifactUNB record {|
    record {| string syntaxId; string syntaxVersion; |} syntaxIdentifier;
    record {| string id; string qualifier; |} sender;
    record {| string id; string qualifier; |} recipient;
    record {| string date; string time; |} dateAndTime;
    string controlRef;
|};

public type EdifactUNH record {|
    string messageRef;
    record {|
        string messageType;
        string version;
        string release;
        string controlAgency;
    |} messageIdentifier;
|};

public type EdifactHeaders record {|
    EdifactUNB unb;
    EdifactUNH unh?;
|};

public type EdifactUNT record {|
    int segmentCount;
    string messageRef;
|};

public type EdifactTrailers record {|
    EdifactUNT unt;
|};
```

### 3. New public API functions

#### Tier 0: Schema-free peek
No schema is needed. Useful before any schema is loaded.

```bal
// X12: ISA is a fixed 106-character segment; field delimiter is ISA[3].
// Parses ISA and, if present, GS.
public isolated function peekX12Headers(string ediText) returns X12Headers|Error;

// EDIFACT: reads UNA service string advice (if present) to detect delimiters,
// then parses UNB and UNH.
public isolated function peekEdifactHeaders(string ediText) returns EdifactHeaders|Error;
```

#### Tier 1: Schema-driven header-only parse
Reads only the segments declared in `schema.headerSegments` and stops. Does not scan the rest of the document.

```bal
// Requires schema.headerSegments to be non-empty.
// Returns: EdiError if schema.headerSegments is empty (old schema guard).
public isolated function headersFromEdiString(string ediText, EdiSchema schema) returns json|Error;
```

#### Tier 2: Envelope parse (one full pass)
Parses `headerSegments`, collects body segment strings (unparsed), then parses `trailerSegments`.

```bal
public type EdiEnvelope record {|
    json     headers;   // parsed against schema.headerSegments
    string[] body;      // raw segment strings: the transaction body
    json     trailers;  // parsed against schema.trailerSegments
|};

// Requires both schema.headerSegments and schema.trailerSegments to be non-empty.
// Returns: EdiError if either is empty (old schema guard).
public isolated function envelopeFromEdiString(string ediText, EdiSchema schema) returns EdiEnvelope|Error;
```

#### Tier 3: Deep parse (existing, unchanged)
```bal
public isolated function fromEdiString(string ediText, EdiSchema schema) returns json|Error;
```

### 4. Backward compatibility and error handling
| Scenario | Function | Result |
|---|---|---|
| Old schema (no `headerSegments`/`trailerSegments`) | `fromEdiString` | Works as before |
| Old schema | `headersFromEdiString` | `EdiError`: "Schema 'X' has no headerSegments defined. Regenerate using edi-tools." |
| Old schema | `envelopeFromEdiString` | `EdiError`: "Schema 'X' is missing headerSegments or trailerSegments. Regenerate using edi-tools." |
| Old schema | `peekX12Headers` / `peekEdifactHeaders` | Works; no schema required |

### 5. Composability
The tiers compose naturally:

```text
Incoming EDI
     |
     +-- [no schema yet] --> peekX12Headers()         ISA/GS  --> choose schema / route
     |                      peekEdifactHeaders()      UNB/UNH --> choose schema / route
     |
     +-- [schema loaded] --> headersFromEdiString()   stops early --> route / audit
     |
     +-- [schema loaded] --> envelopeFromEdiString()  one full pass
     |                         +-- headers (parsed) --> validate envelope
     |                         +-- body (strings)   --> forward / split
     |                         |    +-- fromEdiString(segment) on demand
     |                         +-- trailers (parsed) --> segment-count check
     |
     +-- [schema loaded] --> fromEdiString()          full deep parse (existing)
```

### 6. `peekX12Headers` implementation notes
`ISA` is fixed-width (106 bytes). The field delimiter is at position 3 (0-indexed). Fields are:

| Index | Field |
|---|---|
| 1 | Auth Info Qualifier (2 chars) |
| 2 | Auth Info (10 chars) |
| 3 | Security Qualifier (2 chars) |
| 4 | Security Info (10 chars) |
| 5 | Sender Qualifier (2 chars) |
| 6 | Sender ID (15 chars) |
| 7 | Receiver Qualifier (2 chars) |
| 8 | Receiver ID (15 chars) |
| 9 | Date (6 chars) |
| 10 | Time (4 chars) |
| 11 | Version (1 char) |
| 12 | Control Number (9 chars) |
| 13 | Usage Indicator (1 char) |
| 14 | Component separator (1 char) |

After `ISA`, the segment delimiter is `ISA[16]`. The next segment is read; if it starts with `GS`, it is parsed into `X12GS`.

### 7. `peekEdifactHeaders` implementation notes
If the text starts with `UNA`, the 6 characters following `UNA` define: component separator (pos 3), field separator (pos 4), decimal notation (pos 5), release indicator (pos 6), reserved (pos 7), segment terminator (pos 8).

Otherwise defaults are: component `:`, field `+`, release `?`, segment `'`.

Parse `UNB` using detected delimiters to `EdifactUNB`.
If the next segment is `UNH`, parse it to `EdifactUNH`.

## Alternatives

### A. Single `parseEdiString(depth)` function with a depth parameter
Rejected. A union-return or `anydata` return collapses type safety. Separate named functions make the intent explicit and allow the compiler to enforce return types.

### B. Lazy/streaming parser
Rejected for now. Streaming adds significant complexity (iterators, resource cleanup) and is deferred to Future Work. The proposed design leaves room for it.

### C. Return `X12Headers|EdifactHeaders` from a single `peekHeaders` function
Rejected. A union return forces callers to type-switch. Separate `peekX12Headers`/`peekEdifactHeaders` functions are explicit and idiomatic in Ballerina.

## Testing
Unit tests in `module-ballerina-edi`:

- `peekX12Headers`: valid ISA, missing ISA, truncated input.
- `peekEdifactHeaders`: with UNA, without UNA, missing UNB.
- `headersFromEdiString`: schema with `headerSegments`, old schema (expect error), X12 and EDIFACT inputs.
- `envelopeFromEdiString`: schema with both fields, old schema (expect error), verify body raw strings, verify trailers.
- Backward compatibility: existing `fromEdiString` tests continue to pass unchanged.

Integration tests in `edi-tools` (follow-up):

- Generated schemas include `headerSegments` and `trailerSegments`.
- Generated typed wrappers (`headersFromEdiString`, `envelopeFromEdiString`) compile and return the correct types.

## Risks and Assumptions
- Risk: `peekX12Headers` relies on the ISA segment being fixed-width (106 bytes). If an implementation deviates, parsing will produce incorrect field boundaries. Mitigation: ISA fixed-width layout is defined in the X12 standard and is not configurable.
- Assumption: EDIFACT UNA, when present, always immediately precedes UNB with no intervening whitespace.
- Risk: Callers passing old schemas to new functions receive errors, which may break existing code that upgrades the library. Mitigation: The error message explicitly instructs the user to regenerate the schema.

## Dependencies
- `ballerina/edi` module (this proposal).
- `edi-tools` follow-up to auto-populate `headerSegments`/`trailerSegments` during schema conversion.

## Future Work

- `edi-tools` auto-populate `headerSegments`/`trailerSegments` in `convertX12` and `convertEdifact`.
